# v0.1.11a25

One fix, and it very likely explains most of this project's "nothing happened" history.

## The connection instability was our own diagnostic subscription

`rejected/report` is an exploratory topic that has never been confirmed live. This project's own
code has warned for a while that subscribing to an unconfirmed topic causes immediate
"Unspecified error" disconnects — and it was being subscribed to unconditionally in every
region-command test run.

A field log made the mechanism impossible to miss: across three stages sent in one session, every
stage that received a delivery confirmation (PUBACK) started a mission, and every stage that did
not got nothing — independent of payload differences that had previously looked meaningful. The
connection is shared between watchers, so one unconfirmed subscription tearing itself down took
the whole thing with it, including the publish a real command needed.

`rejected/report` is now off by default in both `verify_region_commands` and
`verify-mission-timeline`. Across five real runs by three testers it produced zero messages, so
turning it off costs nothing and may fix everything. `--watch-rejected` brings it back for anyone
who specifically wants to test that channel.

This also retroactively explains earlier "nothing happened" results from other testers whose
sessions had no PUBACK either — very likely never delivered, regardless of anything about the
region-command payload itself.

793 tests passing, ruff clean.
