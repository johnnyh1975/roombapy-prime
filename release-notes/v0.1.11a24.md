# v0.1.11a24

One finding, from one field run, that explains a result this project had been treating as a
protocol mystery.

## The region-command mystery was, in at least one case, the wrong robot

A tester's account holds two robots: a Roomba 980 (classic protocol) and a Prime one. Every
region-command session went to the **980** — because the library picked whichever robot came
first in a dictionary and told nobody.

The proof was sitting in the same log the whole time: that robot's `ro-currentstate` shadow came
back `404 No shadow exists with name`. Every V4 device has that shadow; no classic one does. The
command was being sent to a robot that cannot speak this protocol at all.

## What changes

- **The library refuses to guess.** `primary_blid()` now raises on a multi-robot account and lists
  each robot with the exact `--blid` value to pass.
- **The tools ask, and help.** They print every robot on the account, mark which ones this library
  can actually talk to, and offer the single Prime one as the default — Enter is enough.
- **A mismatched favorite blocks the send.** If the favorite you picked belongs to a different
  robot than the command targets, nothing is sent, and the message names the BLID to use instead.
  `--i-know-the-robot-id-differs` overrides it for anyone confirming the negative deliberately.

## Why the tools mark rather than auto-select

The SKU table that distinguishes the generations is explicitly incomplete — several platforms in
it have never been seen on a real device. An unrecognised SKU therefore means *unknown*, not
*classic*. Choosing automatically would put a partly-inferred table in the path of a command that
moves someone's robot, so the tools state what they know and leave the choice with you.

That table has also moved into this library from `ha_roomba_plus`: it is protocol knowledge, the
tools need it too, and two copies would drift apart.

## Also fixed

Household lookup assumed a robot's account id and its BLID are the same string. Where they differ
it silently found nothing, which would have broken schedule writes for reasons that would have
looked like anything but an identifier mismatch.
