# roombapy-prime 0.2.0b3

A crash fix, and two findings from testers that changed what this library knows.

## The report helper was the thing that crashed

`Report.add()` looked its status up in a dict with no fallback. It raised `KeyError` on `"FAIL"`, and
— after that call site was corrected and a test written for it — again on `"SKIP"`.

Both times a check that had **finished cleanly** turned into a Python traceback, and the final
summary crashed on the way out too. So a tester saw a stack trace instead of the result they had
just produced.

The first fix had the wrong shape: it corrected the call site, which left the next typo free to do
exactly the same thing. The lookup itself now accepts both short forms and falls back to a neutral
marker for anything unrecognised. A third instance of the same pattern was then found by searching
for it rather than waiting.

## `operatingMode` means two different things

A tester's mid-mission capture had the answer in it, side by side:

    the schedule's command   regions[].params.operatingMode = 32
    the mission status       cleanMissionStatus.operatingMode = 6

Same field name, same moment, different numbers — because they are different things.

**In a command** the number names the requested job: 32 asks for a combined vacuum-and-mop run.
**In the mission status** it is a bitmask of what is currently engaged: 6 is 2|4, vacuuming and
mopping at once, which is how a combo job executes.

That resolves a value that had looked impossible against the command table, and corrects an earlier
conclusion drawn from a vacuum-only robot — where only one bit is ever available, so the field looks
static when it is not.

Still unresolved: vacuum-**then**-mop, where the two run in sequence rather than together.

## Diagnostics were leaking a password hash

`ro-configinfo.passwordHash` was not redacted. A tester found it in his own export and removed it by
hand before attaching the file to a public issue.

The redaction set had been assembled from fields somebody happened to notice, never from asking what
a *category* of secret looks like. There are now two layers: named fields, and a substring check on
every key at every depth for anything containing `password`, `token`, `secret`, `apikey`,
`credential` or `passphrase`.

Verified against field names that appear in no capture — `wifiPasswd`, `authToken`, `deviceSecret` —
which are exactly the ones a hand-written list would miss.

## Confirmed on real hardware

**All three dock commands work**, with the dock reacting within a second of each press:
`evac`, `washpad`, `stoppaddry`. That command path had never been sent to a robot before.

**Map orientation** works in radians, as documented.

**Favourite reordering** appears to sort alphabetically rather than honour the requested position —
so that endpoint does not do what its name suggests.

911 tests passing.
