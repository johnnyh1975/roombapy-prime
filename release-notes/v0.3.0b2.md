# roombapy-prime 0.3.0b2

Three fixes, all from @DaRealGuGu's first run on b1 — including the first concrete lead on a wall
this project has been staring at for a week.

## We may have been evicting ourselves

His run had the iRobot phone app closed and Home Assistant stopped, exactly as asked, and it still
failed. The log says why that matters:

```
08:19:14  reconnecting (0 persistent subscriptions to restore)
08:19:14  connecting ... client_id=app-roombapy-prime-XQWR87YE0
08:19:18  no SUBACK ... disconnect reason: Unspecified error
```

**The same client id, twice, four seconds apart.** AWS IoT drops the older connection when a second
arrives using the same id — and with nothing external left running, the only thing that could have
been on the other end of that was us.

`disconnect()` closes our socket. It does not guarantee the broker has released the session.
Reconnecting under the same id while it still holds one is the eviction case with both ends ours.

**Every reconnect now gets its own client id.** The id is ours to choose and nothing depends on it
persisting across a reconnect. `replace_token()` keeps the caller's id, because there the caller
just chose one.

This is a lead, not a diagnosis. It fits the three symptoms three accounts reported, it explains why
a *first* read sometimes succeeds, and it costs nothing to be wrong about.

## `get_firmware_raw()` crashed on an attribute that does not exist

`PrimeRobot` has no `.sku` — it lives on the login entry. Written yesterday from the vendor's model
and never run, which made it **the fifth invented attribute in a single day.** He found it on the
first attempt.

The sku is now a parameter and nothing else. A caller who has one passes it.

## The timeline request is accepted

Confirmed on an N185240: the publish went through and returned immediately, with
`timelineRequestId=1`. That path was built from the vendor's model and had never been sent to a
robot.

**Whether a report follows is the next question** and needs a watcher running alongside — the
docstring now says so rather than leaving it open.
