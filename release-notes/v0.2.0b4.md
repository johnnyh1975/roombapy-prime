# roombapy-prime 0.2.0b4

One new read-only check, and a message that was actively misleading.

## `verify-writes schedules` — new, read-only

Lists **every** household on the account and what schedules each returns. Writes nothing, needs no
consent flag.

It exists because a tester whose schedules demonstrably fire — his missions carry
`initiator: cloud` — was told by two separate code paths that he has none. Both call
`get_schedules()` with a single household id, and an empty answer cannot distinguish "no schedules"
from "wrong household".

His account has a Classic and a Prime robot, which is exactly the shape where household lookup has
gone wrong here before: the two generations carry differently-shaped identifiers.

Three outcomes, all useful:

- **one household has the schedule** — the lookup is picking the wrong one, and the fix is clear
- **none has it** — these schedules do not live at this endpoint, and everything built on it needs
  rethinking
- **an error on one household** — the reason is in the output

## The schedule check was telling people to create what they already had

When `get_schedules()` came back empty, the message said the account has no schedules and suggested
creating one in the iRobot app.

It now prints how many containers came back for which household id, and says plainly that an empty
answer means either thing — with a note that if the app *does* show a schedule, that is a finding
worth reporting rather than a reason to create another.

## `operatingMode` fully resolved

A capture taken during the mopping half of a scheduled vacuum-then-mop run closed a question that had
been open for two days:

    command   regions[].params.operatingMode = 512   (vacuum then mop)
    status    cleanMissionStatus.operatingMode = 4   (mop only)

The whole sequence from one robot: 2 while docked, 6 during a combined run (2|4, both engaged),
4 during the mopping half.

So the status field tracks the current activity, including inside a two-phase job. The command
numbers are a separate table and never appear there — reading one against the other is what made 6
look impossible.
