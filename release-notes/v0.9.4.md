# roombapy-prime 0.9.4

**A Classic robot over the cloud, when the caller asks for it.**

0.9.3 moved the Vac and Combo Essential to Classic, and
`CloudAccount.prime_robot()` refuses a Classic robot. A caller that had
set up an Essential as a PrimeRobot before -- where, for some users, it
worked -- lost it with the upgrade.

- `prime_robot(blid, allow_classic=True)` builds the PrimeRobot all the
  same. The default stays False, so nothing changes for a caller that
  does not pass it.
- What a Classic robot answers over this path is known only for the
  Essentials: they take its commands, and on some the cloud refused the
  status subscriptions. The caller decides.

## Tested

- The library's tests pass on Python 3.11 and 3.14. The new test builds a
  PrimeRobot for a Classic SKU with `allow_classic=True` and fails without
  the change; the existing one still checks that a Classic robot is
  refused without it.
