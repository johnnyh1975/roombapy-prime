# roombapy-prime 0.8.1

**No file read at a lookup.**

0.8.0 brought the Classic app's error texts as a 500 KB table, read the
first time a code was looked up. In Home Assistant that first lookup
was a sensor's first state write, inside the event loop, and Home
Assistant said so:

    Detected blocking call to read_text ... inside the event loop

- **`vendor_errors_classic`** reads its table when the module is
  imported. Every lookup after that is a dictionary access.
- **`vendor_reference`** does the same with `vendor_reference.json`,
  which was read the same way.
- Importing these modules costs about 8 and 3 ms. `roombapy_prime`
  itself imports neither; only a caller that imports them pays.
- **A table that cannot be read** does not break the import. The first
  lookup reads it itself and raises there, as in 0.8.0.

Nothing else changes: same texts, same functions, same results.

Roomba+ 4.5.0b3 already reads the table at start-up itself and works
with 0.8.0 or 0.8.1.
