# roombapy-prime 0.4.0b2

Fixes from the first field test of 0.4.0b1, on a Roomba 980 — and the
first measurement of the question 0.4.0 left open.

## What the Roomba 980 answered

`roombapy-prime-verify-classic-cloud` compares the Classic app's form of
three cloud calls with the Prime app's. On a Roomba 980 (R980040):

| Call | Classic form | Prime form |
|---|---|---|
| Mission history, page size | `count` **ignored**: 10 asked, all 33 missions returned | `maxReports` honoured: 10 asked, 10 returned |
| Mission history, paging | `before` **ignored**: the same 33 missions again | `exclusiveStartTimestamp` works: the next 10, all older, none repeated |
| Mission history, fields | — | the same fields as the Classic answer |
| Favorites | the account's favourite | **nothing** with `app_edition=1` |
| Part counters | three parts at `-1`, no minutes: the cloud does not track a 980's consumables | — |

So on this robot the Classic history parameters do nothing, and the
Prime ones do what they say. Nothing changes in the clients yet: the 980
is the oldest Classic platform, and the same measurement on an i-, j- or
s-series robot comes before the history call is unified. Favorites keep
their Classic form either way.

## Fixed

- **The certificate hint named the wrong Python.** The tester's Mac had
  Python 3.14 from python.org, without the one-time certificate install.
  The diagnosis was right — a local trust store, not an iRobot outage —
  but the path it gave was `/Applications/Python 3.13/`. It now names the
  Python that is running.
- **"pip install --upgrade certifi" alone changed nothing.** Login and
  REST requests use Python's default SSL context, which does not read
  certifi. The hint now says how to point it there:
  `export SSL_CERT_FILE="$(python -m certifi)"`.
- **`examples/classic_cloud.py`** printed a named robot's name instead of
  its BLID, which every diagnostic tool asks for, and a part the cloud
  does not track as "-1 %". It prints the BLID beside the name, and such a
  part as "not tracked by the cloud".
- **`roombapy-prime-verify-classic-cloud` could not test Prime paging.**
  It paged both forms from the Classic page's oldest record. On the 980
  that page held every mission, so the Prime second page was empty
  whatever `exclusiveStartTimestamp` did. Each form now pages from its own
  first page, and the report judges page size, fields and paging per
  form instead of asking whether two differently sized answers match.

## Install

```bash
pip install "roombapy-prime-tools==0.4.0b2"
```

The tools pin the library to the same version, so this installs both.
Python 3.11 or newer; on a Mac with Python from python.org, run its
**Install Certificates.command** once.
