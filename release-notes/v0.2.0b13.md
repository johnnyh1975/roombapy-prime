# roombapy-prime 0.2.0b13

Required by Roomba+ **v4.0.0a25**.

Three things that were modelled from the app's source and had never been seen on the wire.
All three are now confirmed, and one of them was wrong.

## The live-map heading was half a turn out

The parser added 3.1415927 to the wire angle. No comment explaining it, nothing in the evidence
notes, and a test that asserted `0.0 + 3.1415927` — a tautology that restates the parser rather than
checking it against a robot.

It survived because nobody could see it: the marker was never drawn, so the angle it was drawn at
was never visibly wrong. The first observation of that value in the project's history came the day
the marker started appearing, and the line pointed out of the **back** of the robot.

Removed. If it turns out to be backwards, the line points out of the back — which is where it
already was, so this cannot cost anything.

## Mission history and time estimates are modelled

Both endpoints existed and neither response had ever been seen.

**Mission history** returns a bare array — confirmed from the app's own restservices package, which
returns `List<MissionHistory>` with no envelope class in 63 files. The `missions` and `history` keys
the parser also accepts were guesses; they are kept as a fallback and documented as unreachable.
Four minute fields exist and are not interchangeable: `durationM` is wall clock, `runM` is time
actually cleaning, and a robot that charges halfway through reports a wall-clock figure several
times its cleaning time.

**Time estimates** return three levels in one response — whole mission, per map, per room and zone —
with several estimates per room distinguished by cleaning parameters. The unit travels in the
payload rather than in the field name, so it does not have to be assumed: the previous test used
`{"minutes": 30}`, invented, where the real key is `estimate` beside `"unit": "minute"`.

`confidence` distinguishes good, partial and poor. A percentage built on a poor estimate looks
exactly as authoritative as one built on a good estimate, so poor ones are excluded rather than
shown.

## A new read-only check

`mission_history` reports the shape of that response rather than its contents, and says explicitly
when a response carrying missions parses to nothing — an envelope mismatch and an empty history look
identical otherwise.

1,050 tests passing.
