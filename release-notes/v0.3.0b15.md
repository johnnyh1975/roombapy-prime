# roombapy-prime 0.3.0b15

b14 widened the zone-name search from one layer to three. It made no
difference, and finding out why is the whole of this release.

## The real bug was one level up

The three-layer fix above would not have worked on its own, and finding
out why is the more useful half of this release.

`_zone_names_from_bundle` read `getattr(bundle, "zone_layers", None)`.
`parse_map_bundle` returns a **dict** — `{filename_without_extension:
content}` — and never had a `zone_layers` attribute at all. So the
expression evaluated to `None` on every bundle ever passed to it, and
the function returned `{}` unconditionally.

Widening the search from one layer to three changed nothing, because
the loop was iterating an empty dict. Same mistake one level up:
concluding absence from a search that never ran.

**Three tests agreed it worked.** Each built a fixture with a
`zone_layers` attribute, matching what the reading code reached for. A
mock that agrees with the code proves the code agrees with itself. The
tests now construct bundles from the field names confirmed in
`map_bundle.py` — a `CleanZoneFeature` carries `id` on the feature and
`name` inside `properties` — rather than from what the parser expects.

**And the tool now prints what the bundle contains.** Reporting
"nothing found" without naming where it looked is unfalsifiable from
outside, which is precisely how a typo survived as a claim about
someone's data.
