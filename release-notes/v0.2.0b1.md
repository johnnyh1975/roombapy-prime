# v0.2.0b1 — first beta

The virtual-wall write path works, confirmed on two independent accounts including a full
round trip. That was the last thing standing between this library and a beta.

## What changed since 0.1.11a31

Nothing in the code. This release is the version number catching up with what a31 already did —
which is the point of a beta: a version that has been used, not one that has just been written.

## Why it is a beta now

Two criteria were set out in the write-path test status, and both are met.

**Virtual wall writes work.** The `virwall` array starts with a count of the walls before the walls
themselves — found by dumping the app's serializer bytecode unfiltered, after several filtered
passes had missed the four relevant lines.

Confirmed on two accounts:

- Four zones of two types (3× keep-out, 1× no-mop) in one command, accepted with a new map version
- A single keep-out zone, written, **read back on the new map version unchanged, and written
  again** — the round trip that separates "the server accepted it" from "it is actually stored"

**One quiet round with no public-signature changes.** a27 changed `Region.to_json()` and a28/a29
changed `edit_map()`. a30 and a31 changed neither, so the surface this beta stabilises is the one
that has been in testers' hands.

## What that investigation cost, and what it taught

Three testers between them eliminated list length, zone type mixing, map count, account, map
version, our own zone filtering and all three request-envelope variants. None of it mattered: the
payload failed at element zero, before any of those reached the deserialiser.

The `500`-rather-than-`400` response was noted repeatedly and read as a wrong *type* inside a wall.
It was an extra *element* before the walls.

Two process notes came out of it, both now in the internal docs:

- **When every filtered pass says "everything matches", dump the raw code.** `grep` on a
  decompiled serializer will hide a line that does not mention any of the names you are searching
  for.
- **A tool that reports a local crash as a server answer costs a tester an evening.** a28 died with
  a `TypeError` before anything left the machine and announced that `response_type` had been ruled
  out. It had not. Two testers lost a session to that before the wrapper signature guard existed.

## New: one tool for the write operations nobody has ever run

Nine of this library's twenty-one write operations have a dedicated verifier. Twelve were built
from decompiled app code and have never been sent to a real robot — the same starting position that
let `set_virtual_wall` look complete while failing for months.

Twelve more scripts would not have been run. A tester called a single existing tool "all just Greek
to me", and he is right: the barrier is not willingness, it is working out which command to type.

So there is one:

```bash
roombapy-prime-verify-writes --list
roombapy-prime-verify-writes set_map_name --new-name "Test" \
    --i-understand-this-writes-to-my-robot
```

Five operations, each with a risk level, and — the part that matters — **what to look at in the
iRobot app afterwards**. A write this library reports as accepted is not the same as a write that
did what you expected; that distinction is what the whole virtual-wall investigation turned on.

`delete_map`, `reset_robot` and `reset_robot_parts` are deliberately absent. Deleting a map costs
weeks of mapping and every zone on it; the resets are irreversible. A confirmation prompt is not
enough protection for something a person may try while working through a list in a language they
only half follow.

## Known and unchanged

- `schedHold` writes and reads back successfully and the robot ignores it entirely.
- Robot settings `childLock`, `ecoCharge`, `noAutoPasses` and `vacHigh` write and read back;
  `childLock` additionally has a confirmed audible effect.
- The map bundle's `borders`, `floorTypes`, `cleanZones` and `dockPose` models are now
  field-confirmed against two real captures — borders are `MultiPolygon`, floor types carry
  `"carpet"` under the wire key `type`, and the dock reports an `orientation`.

591 core tests plus 311 for the CLI tools, all passing.
