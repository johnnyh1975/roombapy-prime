# v0.1.11a26

Two confirmations from real hardware, and a set of connection fixes that explain a long trail of
inconclusive results.

## Robot settings writes are confirmed working

All five settings wrote and read back successfully on a real device. **`childLock` is confirmed
end to end** — the change appeared in the iRobot app and the robot announced it audibly. That is
the first setting whose physical effect is confirmed rather than only its acceptance.

## `schedHold` is accepted but does nothing

Write accepted, read-back confirmed, schedule still active in the app. Writing it to `rw-settings`
is evidently not the mechanism the app uses.

The way this surfaced is worth noting: the cross-check against the classic shadow flagged the
divergence — one source said enabled, the other still said disabled — **before** anyone looked in
the app. The app then confirmed it. So that cross-check is a real signal, not a curiosity, and
`verify-settings-write` now warns before toggling this particular setting. Otherwise you see five
green checkmarks and reasonably conclude it worked.

## The connection was killing sends, in three separate ways

A regression from a25 came first: turning off the `rejected/report` subscription left the watch
window being handed a `None` task, which killed it instantly. Every stage then printed "no events
observed" — including one where the robot visibly started a mission. The robot's own mission
counter gave it away, jumping from 35 to 37 with no 36 in any log.

Underneath that were two older problems, both the same shape. `get_shadow()` had always revived a
dead connection before using it; **publishing and subscribing did not**. Publishing into a dead
connection is the worst case available here — no error, no delivery confirmation, and the script
then reports that missing confirmation as though it meant something about the payload. Subscribing
into one is worse still, because it fails completely silently and the watcher simply sees nothing.

Field logs showed all three symptoms of a single dead connection in one place: a failed subscribe,
a timed-out shadow read, and a missing delivery confirmation — with only the middle one visible as
an error.

Every operation now checks the connection is alive first; previously two of seven did. Keepalive
also drops from 300 seconds to 60, because at 300 a broken connection went unnoticed for up to
450 seconds.

806 tests passing, ruff clean.
