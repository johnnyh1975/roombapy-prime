# roombapy-prime 0.9.3

**The Roomba Vac Essential and Combo Essential are Classic robots.**

SKUs starting `Q0` (Vac Essential) and `Y0` (Combo Essential) were listed
as Prime, from app code that had never been checked on a robot. The Prime
app's own model table (3.2.0) has neither, and iRobot Home 7.18 knows them
as its own (CongoVacuum, CongoCombo).

Three Combo Essentials (SKU `y014020`, firmware congo 1.1.22), reported by
@gloopy-purple-liquid in ha_roomba_plus, had run on the local connection
of Home Assistant's built-in integration. Set up as Prime from the
account, the cloud broker refused every status subscription for them, so
their state never changed after the first read.

- `is_prime_sku()` is now False for them, and `sku_generation()` returns
  `"classic"`.
- Nothing else changes. A caller that already holds such a robot as Prime
  has to set it up again on the local connection.

## Tested

- The library's tests pass; the test that pinned `Q0` to Prime now pins
  `Q0` and `Y0` to Classic and checks that the Prime 105 and 115 SKUs next
  to them stay Prime. It fails without the change.
