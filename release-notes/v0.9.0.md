# roombapy-prime 0.9.0

**Prime robots of one account share one MQTT connection, and stop
evicting each other.**

## Two robots, one client id

One iRobot login gives every robot of an account one connection token,
and the token one client id. AWS IoT allows one connection per client
id: when a second one connects, it drops the older one.

`CloudAccount.prime_robot()` gave each robot a connection of its own,
so two Prime robots on one account took turns dropping each other,
every couple of seconds, for as long as both ran. @Baby-scarf counted
about 120 drops in five minutes on each robot, for hours; @mattdmrc
reported the same in #91. The library's own warning pointed at another client on the
account, which was right about the mechanism and wrong about the other
client: it was the robot next door.

## One connection per token

The robots of one token now share one connection:

- `CloudAccount.prime_robot()` hands each robot a **channel**
  (`RobotChannel`) of the account's connection for its token. Topics and
  requests name the robot; the connection is the same.
- A drop is **rebuilt once and logged once** for every robot on it, and
  the token is **renewed once**: each robot's refresh wakes for it, and
  the second finds it renewed (`ConnectionShare`, one lock and one drop
  record per connection).
- `robot.disconnect()` closes **the robot's channel**. The connection
  closes with the last one, so unloading one robot leaves the others
  connected.
- A robot added after a new login joins its companions' connection,
  found by the client id it uses now or by the robots its token names.

Checked first on a real account: @Baby-scarf ran
`roombapy-prime-verify-shared-connection` with two Prime robots, one
connection, for 75 minutes, across a token refresh, with no drop and
every request answered.

## For callers

- Nothing changes for one robot, or for robots built through
  `CloudAccount`.
- A robot built with `PrimeFactory` alone still has a connection of its
  own. Two of those on one account evict each other; build several robots
  of one account through `CloudAccount`. `PrimeFactory.create_prime_robot()`
  takes a `mqtt_client` to share one.
- Every `PrimeMqttClient` method that names a robot takes `blid`,
  defaulting to the robot the client was built for.

## Also

- `roombapy-prime-verify-shared-connection` says how long it ran: a run
  stopped after two minutes read "0 in 75 min", now "0 in 2 of 75 min"
  (@Baby-scarf).

## Tested

- The library's suite and the tools' suite pass; ruff, strict mypy and
  the per-module coverage floors pass.
- New tests run two robots of one account over a fake broker that drops
  the older connection with the same client id, as AWS IoT does: one
  connection, both delivering, a drop rebuilt once, one renewal, and the
  connection closing with the last robot. All of them fail on 0.8.3.
- Roomba+'s suite passes against this version.
- **Not yet confirmed in Home Assistant** with two robots: a beta of
  Roomba+ on 0.9.0 does that.
