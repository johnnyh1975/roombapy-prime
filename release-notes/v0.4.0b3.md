# roombapy-prime 0.4.0b3

Classic mission history can now be paged.

## Paging a Classic robot's mission history

`roombapy-prime-verify-classic-cloud` has now run on two Classic
generations. They agree:

| | Roomba 980 (R980040) | Roomba i7 (i755840) |
|---|---|---|
| `count=10` (Classic) | ignored: all 33 missions | ignored: all 67 missions |
| `before` (Classic) | ignored: the same 33 again | ignored: the same 67 again |
| `maxReports=10` | 10 returned | 10 returned |
| `exclusiveStartTimestamp` | the next 10, all older, none repeated | the next 10, all older, none repeated |
| fields | the same in both forms | the same 31 in both forms |

The new `ClassicRestClient.get_mission_history_page(blid, *, before=None,
page_size=100)` sends:
- `maxReports` and `exclusiveStartTimestamp`, with the Classic filter
  and done codes;
- no `app_id`;
- key for key, in the same order and with the same signature as
  `PrimeRestClient.get_mission_history()` with those values.

The parameter names come from `FetchMissionHistoryRequest`. The Roomba
Home app 3.0.0 does not page at all: it asks with `maxAge=10`. What the
server does with them is what the two measurements above show.

`get_mission_history()` is unchanged. It is the request ha_roomba_plus
has always made for its regular refresh. Its docstring now says that
`count` and `before` do nothing.

Not measured: a page size other than 10. The default is 100, the Classic
app's own count. A caller that pages should treat an error as "no
further pages".

Favorites keep their Classic form: with `app_edition=1` the i7 returned
none of its 7 favourites, and the 980 none of its one.

## Known broken: a robot dropped out of its account

A Roomba Plus 505 Combo bought second-hand disappeared from the Roomba
Home app three times, each time right after the validator logged in.
Signing out of every phone and back in through the app did not do that.
The cause was not found:
- The login sends nothing that adds, removes or moves a robot. An
  analysis of the Roomba Home app found no such field either.
- The same login works on every other account tested.

The README lists it under "Known broken".
