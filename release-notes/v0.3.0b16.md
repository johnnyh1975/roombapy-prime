# roombapy-prime 0.3.0b16

b15 fixed the zone-name reader. This fixes the call that never got as far
as it.

## `--list-rooms` never reached the bundle

`get_map_geojson_link` returns the whole response dict;
`download_map_bundle` wants the URL string out of it. Passing the dict
raised `Constructor parameter should be str` from yarl — a message that
reads like a type bug in the library rather than a mistake at the call
site.

`verify_map_edit.py` has extracted the URL correctly all along. Two
implementations of the same three lines, one of them wrong, and the
wrong one was the one the zone-name question depended on.

## The diagnostic that only printed when it was not needed

b15 added a line naming what the bundle contains, so that "nothing
found" could be checked from outside. It sat after the `except` block —
so on a run that failed, which is exactly when the question arises, it
never printed. @chairstacker's report shows the error and no contents
line at all.

Moved, and the failure message now names the exception type too.
