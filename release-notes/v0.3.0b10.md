# roombapy-prime 0.3.0b10

One field report, one bug that had been wrong since it was written.

## The map bundle was never readable

@chairstacker ran the map-edit verifier and got:

```
0 room feature(s) found across all map bundles
```

On a robot with **seven named rooms**.

`_fetch_bundle_rooms` read `parsed["rooms"]` expecting a bare list. A
bundle file is a GeoJSON collection — `{"type": ..., "features": [...]}`.
The type check failed and the loop moved on, silently, because "skip
this map" and "this map is empty" look identical from the outside.

Both shapes are accepted now. `borders` really is a bare feature
(confirmed session 58); `rooms` and `cleanZones` are collections.

**This mattered beyond the one tool.** The same reader is what the Home
Assistant integration uses to find zone names, and what
`name-clean-zone` uses to check existing zones before writing — a guard
that was quietly broken until this release.

## `--list-rooms` shows zone names

It read `get_map_metadata` → `rooms_metadata`, which carries **room**
names only. That is why @chairstacker's rooms picked up names after he
renamed them in the app and his eight zones stayed `None`.

Zone names live in the bundle's `cleanZones` layer. Both sources are
read now, with the origin marked per line:

```
room_id='15'   rid   name='Room 1'              [map]
room_id='100'  zid   name='Guest Access Zone'   [bundle]
```

And when the bundle carries nothing, it says so outright rather than
leaving `None` to be interpreted.

**`--dump-config` cannot answer this** — its summary is deliberately
depth-limited so real home layouts stay out of shared reports, and zone
names sit exactly under the cutoff. Four rounds of asking for one would
have produced nothing.

## Upgrading

```bash
pip install --upgrade "roombapy-prime-tools@git+https://github.com/johnnyh1975/roombapy-prime.git@v0.3.0b10#subdirectory=tools"
```

If you only use Home Assistant, this comes with the Roomba+ update.
