# roombapy-prime 0.2.0b16

Required by Roomba+ **v4.0.0a30**.

## A shadow GET is now confirmed to have been sent

`get_shadow()` published its request and discarded both the result code and the handle. A
queued-but-unsent request produces exactly the symptom @DaRealGuGu reported twice: no answer within
eight seconds, no error, and **nothing to distinguish "this robot has no such shadow" from "we never
asked"**.

This is the same class of gap b12 closed for `subscribe` — closed there, left open three lines away.

It does not prove what is failing on his account. It makes the two possibilities tell themselves
apart, which they could not before.

## The tool can produce its own debug log

Asking a tester for one meant telling them to set an environment variable this tool does not read, or
to wrap the call in a Python one-liner. Both were guessed rather than checked.

`--debug` now works. **A check whose failures need a log should be able to produce one.**

## Schedules keep fields we do not model

`is_smart_clean_fav` arrives on real schedules and appears nowhere in APK 2.2.4 — neither in Kotlin
nor natively (APK research 10). Writing a schedule is read-modify-write, so every write silently
dropped whatever the server knows and the app does not.

**And the loss was invisible**: the request is accepted, and the field simply stops coming back.
`ScheduleOptions` now carries everything it does not name, opaque and unchanged.

The point is not this one key. It is that the next one costs nothing.

## Region-targeted cleaning is confirmed on real hardware

`send_routine_command_via_cmd_topic()` carried "EXPERIMENTAL, UNCONFIRMED — a well-reasoned
hypothesis, NOT a confirmed working path". @Echovictor37 confirmed it on a Combo 105 (sku Y311240):
the robot cleaned only the targeted room, and `operating_mode` selected vacuum-only versus
vacuum-and-mop, both visually verified. The exact command shape is now in the docstring.

**A third failure mode came with it.** With `command_type=CLEAN` and `map_id=None`, the broker
returned a PUBACK **and the robot cleaned the whole house** — not the requested room, and not nothing
either.

This project knew two ways a command fails: no effect at all, and a PUBACK followed by silence. This
is a third: accepted, effective, and not what was asked. **A confirmed send proves delivery, never
intent** — which is worth stating plainly, because two guards added this week check delivery and
would both have stayed silent while that robot cleaned every room.

Still untested: `clean_all` through the same path.

1,107 tests passing.
