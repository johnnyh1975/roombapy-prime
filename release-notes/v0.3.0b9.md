# roombapy-prime 0.3.0b9

Three field reports, one decompilation run, and a field that has been
write-only since it was added.

## `DoneCode` was wrong on nine of nineteen values

@chairstacker's `clean_streak` and `area_cleaned_today` both read 0 on
a robot with 128 stored missions. The cause was here.

`DoneCode` came from bytecode constant names in an older APK,
lowercased by analogy with `RegionType`. Only `ok` had ever been
confirmed. App 3.0.0 says the wire values are **abbreviated camelCase**,
and **not one snake_case form appears anywhere in the APK**:

```
success    {ok, busy, dndEnd, returnHomeEnd, timeboxEnd}
cancelled  {cncl, usrSlp, plcDoc, usrEnd, usrSpt, batcncl}
```

So `dnd_end` is `dndEnd`, `cancel` is `cncl`, `place_dock` is
`plcDoc`, `battery_cancel` is `batcncl`.

Worth knowing: `busy`, `dndEnd` and `timeboxEnd` count as **success** —
a mission ended by quiet hours or a time window did its job. `batcncl`
counts as cancelled rather than an error.

Eight members remain unproven — `battery`, `empty`, `full`,
`incomplete`, `none`, `schedule_error`, `stuck`, `user_reboot`. They
appear nowhere in 3.0.0, not even as the abbreviations the confirmed
values would predict, and are marked as placeholders rather than
findings.

The history endpoint also takes
`supportedDoneCodes=dndEnd,returnHomeEnd`, telling the server which
newer codes the caller understands.

## `region_name` was written and never read

Zone names do not live in the map. @chairstacker's `--list-rooms`
reports `name=None` for all eight of his zones while his app timeline
labels them "Guest Access Zone" and "Living Room @Wall".

Both readings are correct — they are different fields:

```
map      cleanZones[].properties.name       empty on his robot
command  lastCommand.regions[].region_name  carries the names
```

The app's own `IrobotTimelineRegionNameResolver` reads the command. The
timeline events carry no name of their own.

This library wrote `region_name` and never parsed it back. It does now,
as `Region.region_label`, kept separate from the map-side `name`.

## The first observed `digiCap`

@ricrog1135's `W155020` is the first robot anyone has read one from.
Nine capability gates were modelled from iRobot's own tables and none
had ever been seen:

```
{"appVer": 1, "cleaningProfiles": 2, "ddAutomation": 1,
 "timeline": 1, "perspective3DMap": 1}
```

Every key maps to a field this library already declared, and every one
is read. The modelling was right.

Two things the observation adds. The block is **partial** — five of
eleven documented gates, so a robot describes what it has rather than
listing everything with a zero, and an absent gate must stay absent.

And `cleaningProfiles: 2` means nothing. The app types this capability
as `Set<CleaningProfileType>?` and decodes it by matching entries
against `light`, `normal`, `deep`, `smart`. A bare `2` is not that, so
the decoder stores null and **the number is discarded without ever
being interpreted**. The profiles come from `GET /v1/profiles`;
@ricrog1135 is offered all four on the robot reporting 2.

`digiCap.matter` was declared in the key list and **never read** — a
robot reporting it would have lost the value silently. Fixed, with a
guard that checks all eleven documented keys land somewhere.

## Naming a clean zone

New tool: `roombapy-prime-name-clean-zone`.

There is no rename command. `updateCleanZones` reads
`zone, id, name, geometry` per item, keeps what is in `retainIds` and
deletes the rest — so renaming means writing the whole list back with
one name changed.

Confirmed from the decompiled app that this reaches the right place:
reading (`_resolveAreaName`) and writing
(`_convertToP2MapCleanZoneInfo`) use the same field offset. There are
not two name stores.

**The risk is the full replace, not whether the name takes.** Name one
zone and omit the others and the others are deleted. The tool reads the
current list first and refuses to send if it cannot, is a dry run by
default, and needs `--i-understand-this-rewrites-my-zone-list` to write
anything.

It has never been run against a robot.
