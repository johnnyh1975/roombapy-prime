# roombapy-prime 0.8.0

**The Classic app's error texts, so a Classic robot no longer gets the
Prime app's.**

## Why

`vendor_errors` holds the Prime app's texts (Roomba Home 3.2.0), and
callers used them for every robot. The two apps disagree on what some
codes mean, not only on the words:

| Code | Classic app (iRobot Home 7.18.0) | Prime app (Roomba Home 3.2.0) |
|---|---|---|
| 2 | Brushes need cleaning (two rubber brushes) | Main Brush stuck |
| 6 | Stuck near a cliff | Clean Cliff Sensors |
| 47, 228 | Reboot required | Important update available |
| 106 | Battery error, take it off the base | Wait for the battery to cool down |

None of the 71 codes both apps know has the same text in both.

## What is new

- **`roombapy_prime.vendor_errors_classic`**, in the same eight
  languages as `vendor_errors`:
  - `classic_vendor_error(code, language, *, sku=None, clean_base=False,
    imperial=False)` for `cleanMissionStatus.error`: 183 codes.
  - `classic_not_ready_text(number, language, *, sku=None)` for
    `cleanMissionStatus.notReady`, its own namespace, keyed by the value
    the robot reports: 45 values.
  - `classic_dock_text(code, language)` for dock states and dock errors:
    92 codes. The Classic app never reads 450–463 or 501–509 from the
    robot's error field.
  - `classic_help_id(code)` / `classic_help_id(not_ready=n)`: the key of
    the code in iRobot's help catalogue, to link iRobot's own page for
    the robot's model.
- **`vendor_errors.prime_help_id(code)`**: the same key for a Prime robot.
  The two catalogues differ in one place: Prime files charging errors
  under the full code (`Charging Error 104`), Classic under the code
  minus 100 (`Charging Error 4`).
- **The variants the app applies per robot:** by SKU (69x: main brushes
  for 2 and 206; Vac/Combo Essential: centre brush for 2), with a Clean
  Base (36), and in imperial units (74).
- Each lookup returns the app's `title`, `content` and `history`, and a
  derived `label`: the title, unless it is a line shared by a whole
  group ("Error", "Charging error", "Unable to start"); then the history
  line.
- The app's `%s`/`%1$s` come out as `@val`, as in the Prime table. In
  dock texts the bracketed code is filled in.

## Source

`com.irobot.home` 7.18.0 (versionCode 1607180002): strings from
`base.apk:resources.arsc`, code-to-text mapping from `RobotStatusResolver`
and `libcore_jni.so`. The table, `vendor_errors_classic.json`, is iRobot's
text byte for byte; `scripts/generate_vendor_errors_classic.py`
regenerates it from the extraction (`--check` to compare).

## Upgrading

Nothing changes for existing callers: `vendor_errors` is untouched. A
caller that shows error texts should pick the table by the robot's
generation.
