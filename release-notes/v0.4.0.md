# roombapy-prime 0.4.0

The first stable release of the 0.4 line, and the one ha_roomba_plus
4.3 is built on. Its code is 0.4.0b3's, unchanged. Coming from 0.3.4,
this is what is new; the details are in the
[0.4.0b1](v0.4.0b1.md), [b2](v0.4.0b2.md) and [b3](v0.4.0b3.md) notes.

## Both robot generations, one login

- **`CloudAccount`** logs in once per iRobot account and hands out the
  right client for each robot. `generation(blid)` says `"prime"`,
  `"classic"`, or `None` for a SKU it does not know. Every client it
  hands out relogs in through the account, so clients that hit a 403
  together share one login.
- **`ClassicRestClient`** carries the cloud calls of Classic robots
  (900, i, s and j series): maps and room shapes, mission history, part
  counters, favorites, automations. These are the requests ha_roomba_plus
  sent itself up to 4.2.12, moved here unchanged. The tests pin the
  query, the body bytes and the signature.
- **Paging Classic mission history.** The Classic app's parameters
  (`count`, `before`) are ignored by the cloud. `get_mission_history_page()`
  uses `maxReports` and `exclusiveStartTimestamp`, measured to page on a
  Roomba 980 and an i7.

## Errors you can act on

- **Every failure is a `CloudError`**: login, REST and MQTT, including
  dropped connections and timeouts that used to escape as bare aiohttp
  or `TimeoutError` exceptions.
- **`reason`** on every error says why it was raised, as a
  `CloudErrorReason` key an application can translate: `timeout`,
  `account_locked`, `ssl_local_trust_store`, `rate_limited` and others.
- **HTTP status as classes**:
  - `RestClientError` (4xx: don't resend unchanged);
  - `RestRateLimitedError` (429, with `retry_after`);
  - `RestServerError` (5xx: try later).
- **A time limit per request**, 30 s by default (`request_timeout=`,
  `None` for none).

## Fixed along the way

- `repr(LoginResult)` no longer prints robot passwords and cloud keys.
- Certificate failures are diagnosed the same way everywhere. A machine
  without a usable trust store is no longer told to wait for iRobot, and
  the hint names the Python that is running.

## For the command-line tools

`pip install roombapy-prime-tools` now installs the current tools
without `--pre`, including `roombapy-prime-verify-classic-cloud`.

## Known broken

Unchanged from 0.4.0b3: one second-hand Roomba Plus 505 Combo dropped
out of its account after validator logins, cause not found. See the
README.
