# v0.1.11a23

A structural release, no protocol changes. The diagnostic tooling now ships as its own
distribution, and roughly 400 lines of copy-pasted CLI code became one shared module.

## ⚠️ One change for testers — a new install command

Nothing else changes: still one command, and it pulls the library in as a dependency.

```bash
pip install "roombapy-prime-tools@git+https://github.com/johnnyh1975/roombapy-prime.git@v0.1.11a23#subdirectory=tools"
```

All eleven commands keep their names. `--list-favorites`, the safety gates, the staged risk
model — all unchanged.

**Library consumers need to do nothing.** `ha_roomba_plus` installs `roombapy-prime` exactly as
before and simply no longer receives the tooling.

## Why split at all

Not disk space. The tools register **11 console scripts, several of which move a real robot** —
and they were landing on the PATH of every Home Assistant installation that merely consumes this
library. The core distribution now registers **zero** console scripts.

## What else changed

- **Shared CLI scaffolding.** Account arguments, BLID validation and credential prompting had been
  copy-pasted into all ten scripts. The copies had drifted, and the drift caused real bugs: a
  helper that existed under one name in one script and not at all in another (undefined-name
  crash), and three separate cases of a fix landing in a standalone script but not its
  session-runner twin. It also surfaced a user-visible inconsistency — four scripts prompted
  `"Password: "` while six prompted `"iRobot account password: "`. Now uniform.

- **Two new guards, because both failure modes are silent ones.**
  `test_tools_boundary.py` enforces by AST analysis that no core module imports the tooling
  (including imports nested inside functions, which a text search would miss). It also guards
  itself: one test asserts core files were actually found, so a future layout change cannot make
  every check pass vacuously.
  `scripts/check_version_pin.py` verifies the tools pin exactly the core version they ship
  alongside — the one real risk of splitting, since the tools reach deep into the library and a
  mismatched pair fails as a confusing AttributeError in someone's terminal rather than cleanly.
  It caught a genuine mismatch on its first run.

- **Tests for the shared scaffolding itself.** The duplicated copies never had any, and it is now
  reached by all ten scripts — a regression there would break every one at once.

479 core tests + 141 tools tests, all passing, ruff clean in both packages.
